# Design: a customer's document names the org that sent it, never the app

## 1. What it is

The multi-tenant rule: nothing tenant-visible is global unless a per-org setting overrides it. A quote is the
most visible thing an org sends its own customer, and today every org's quote carries AcceleRep's identity.
The map below (§2) was read in code on 9 Nov over `ec4204e`; the census (§3) is a SELECT of the shared `main`.

### 2.1 Where an org's identity is kept today (three places, read in code)

- **Settings → Company profile** (CompanyProfileDetail.jsx): `companyDisplayName`, `companyLegalName`,
  `companyBrandColor`, `companyAddress`, `companyCity`, `companyState`, `companyZip`, `companyCountry`,
  `companyPhone`, `companySupportEmail`, `quoteHeader`. Each in settings.mjs's GET (:185-195), PUT (:422-432) and
  `REV_KEYS` — they persist. The GET's display name falls back to the `company_name` column (:185).
- **Settings → Quote templates & branding → Edit brand** (EditBrandModal.jsx): `quoteBrand` — company name, contact
  line, four colours, two fonts, a logo mark. Persists (settings.mjs:218, :442). **No customer output reads it** —
  only the Settings screens do. Its default, `BRAND_PRESET` (:15-25), is AcceleRep's own identity: "Accelerep",
  "sales@accelerep.com · accelerep.com · +1 (415) 555-0140" — shown to every org's Admin, and stored as the org's
  brand by a Save that changes nothing else. The Quote templates page's own `QT_BRANDING` (QuoteTemplatesDetail.jsx:37-42)
  is the same identity, hard-coded.
- **`companyProfile`** (`{ address, phone, notes }`): a settings key (settingsDefaults.js:74; settings.mjs:162, :409)
  that **no screen writes**. The PDF's D3 branch was built for it.

## 4. The design (recommended)

**R1 — one source for who the org is.** A customer document names the org from its Company profile: the display
name, the address lines, the phone and the support email. When the display name is empty, the name is the org's
own name in Clerk (every org has one; the server already reads it — users.mjs:591 `getOrganization`; the screen has
`organization.name`). Never the app's name. One rule in one file (`src/utils/orgIdentity.js`, `orgIdentityOf`),
used by the screen and the server alike, as `dispatchCustomer.js` is.

**R2 — the server reads it, never the body.** The PDF and the emails read the identity from the settings row of the
caller's org (`auth.orgId`) — the PDF's body-borne `companyProfile` is ignored and the dead key left in place
(settings keys are additive; filed for removal). No request can make an org's quote name another org.

**R3 — the documents.**
- D1, the preview: the identity's name and address; the signature line "<name> signature" (or "Company signature"
  when there is no name at all).
- D2-D3, the PDF: header the identity's name; under it the address, phone and email; Author the org's name; the
  footer the date and the quote number only ("Generated by …" dropped).
- D4, the quote email: header the org's name; footer the org's name with its phone and email; no link into the app.
- D5, the dispatch customer emails: a customer layout of their own — headed by the org's name, no "account on
  Accelerep", no preferences link. The members' layout stays as it is.

**R4 — Edit brand stops presenting AcceleRep's identity.** Its preset's name and contact line are empty (the
colours and fonts may stay as a starting look); the Quote templates page's strip reads the org's identity, not
`QT_BRANDING`. The one org whose stored brand is the untouched preset needs no data change: under R1 nothing reads
`quoteBrand`'s name.

**R5 — the Settings words say what is true.** The Company profile and Edit brand sentences of §2.2 are reworded to
what this batch makes true (the display name, address, phone and email print on quotes); the logo, brand colour,
quote header, colours and fonts are filed as their own feature (§6 below), not promised.

## 5. Questions for Jeff

- **Q1 — the name when the Company profile has none.** (a) The org's name in Clerk (Recommended — every org has one,
  and it is the name its own members chose; UKG's quote would print it). (b) No name at all — the quote prints only
  the quote, until an Admin fills in the Company profile.
- **Q2 — Edit brand's own "Company name" and "Contact line".** (a) Remove both fields from Edit brand; it says
  "Your company's name and contact details come from Settings → Company profile" with a link (Recommended — one
  place to set it). (b) Keep them as a quote-only override of the Company profile.
- **Q3 — where a customer's reply goes (D6).** (a) Reply-to the rep who sent the quote (their email in the org's
  users), and for the dispatch emails the org's support email; the From address stays the one verified sender, its
  display name the org's ("UKG <noreply@…>") (Recommended). (b) Reply-to the org's support email for all. (c) Leave
  replies as they are and change the words ("reply to this email" removed). Resend accepts a `reply_to` per message;
  the sender address must stay on the verified domain.
- **Q4 — the PDF renders the quote from the request body** (quote-pdf.mjs:356 — any signed-in member can post any
  quote content and get a PDF; no org check on the quote, though it prints only the caller's own org's identity
  under R2). (a) File it, its own small batch (Recommended — it changes what an unsaved edit's PDF shows). (b) Fold
  it in: the PDF loads the stored quote by id in the org, by the deal's read rule.
- **Q5 — the brand look (colours, fonts, logo, quote header).** (a) File as one feature, "a quote in the org's
  brand", for after selling-readiness (Recommended). (b) Apply Edit brand's colours to the PDF and preview in this
  batch.
