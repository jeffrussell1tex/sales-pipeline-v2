## How the census was done
- I grepped the scope for `dbWrite(`, `dbFetch(`, bare `fetch(`, `JSON.stringify` (to catch request bodies), `XMLHttpRequest`, `method:`, `bulk.postNew/putBulk`, `addToSettingsList/writeSettings/putSettings`, and every `netlify/functions/` string. I read every dbFetch call's options. The remaining dbFetch calls are GETs and are not listed: App.jsx 543, 557, 754, 770, 1019, 1253 and 1292; useAccounts 25; useActivities 27; useCoachingNotes 44; useContacts 22; useDocuments 78 and 103; useMerge 105, 154 and 196; useOpportunities 40; useQuotes 37 and 56; useSettings 85 and 111; useTasks 37; AppHeader 288 and 331; ModalLayer 786 (roster re-read); ContactRail 323; documentsStorage 221.
- These are the shared words:
  - **dbWrite** (storage.js) never throws. A throw gives `{ ok:false, status:0, error: NETWORK_ERROR }`, where NETWORK_ERROR is `'The server could not be reached.'`. A non-ok answer goes through `refusalOf`, which says `'You do not have permission to make this change.'` for **any 403, without reading the body**. Otherwise it gives the body's `error` (plus ` (ref …)`), or else `The server returned N.`. A 2xx that is not JSON counts as ok with `data: null`.
  - **readRefusal / refusalWords** give the body's `error` string (plus ref), or else `The server returned N.`. A 403 keeps the server's words.
  - **failureWords(e)**: a fetch TypeError gives `'The server could not be reached.'`. A plain Error passes its message through. Anything else, including a SyntaxError from a non-JSON body, gives `'Its answer could not be read.'`.
- "Optimistic" means the screen state changes before the answer.
- "4xx/5xx?" asks whether the code treats a 4xx refusal differently from a 5xx, gateway or thrown request.
